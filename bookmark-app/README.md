# Little Library

Little Library stores bookmarks and folders in Supabase. People sign in with a username and password. Bookmark rows are shared among signed-in accounts; folders remain private to their owner.

## Connect Supabase

1. Create a Supabase project.
2. In the Supabase SQL Editor, run [`supabase/schema.sql`](./supabase/schema.sql) to create the tables, indexes, and row-level security policies. The `bookmark` table stores `title`, `type`, `folder`, `url`, `note`, and `tags`; `id` and `created_at` are generated by the database. The script adds the `url` column if the table already exists without it.
3. Copy `.env.example` to `.env.local` and fill in the project URL and public anon/publishable key from the project API settings:

   ```env
   NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=your-public-anon-key
   ```

   `.env.local` is ignored by Git. Never use a service-role key in the browser or in a `NEXT_PUBLIC_` variable.
4. Restart the app after changing environment variables:

   ```bash
   npm run dev
   ```

5. In Supabase Authentication settings, disable email confirmation for the Email provider. Usernames are mapped internally to reserved `.test` email addresses because Supabase Auth's password flow requires an email or phone; no real email is collected, and those addresses cannot receive confirmation messages. Existing email-based accounts can still sign in by entering their email in the username field.

All authenticated accounts can view and manage rows in the shared `bookmark` table, as selected for this app. Do not use this policy if bookmarks should be private per account.

## Existing device-only data

Bookmarks and folders previously saved in this browser's local storage are not automatically uploaded. They are left untouched in the browser, but the app now reads and writes the Supabase database. To keep those items, do not clear this browser's site data; migrating them is not included yet.
